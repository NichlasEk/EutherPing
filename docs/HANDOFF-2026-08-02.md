## Product state

The app is a working physical-device beta and the latest user report is that it
works fairly well on both GrapheneOS and Samsung hardware.

- `Signals` is the ordinary carrier lane for SMS and unencrypted image MMS.
- `Vessels` is the secure lane for invitations, safety-code verification,
  encrypted text, images, and files.
- Sent and received bubbles have distinct colors and right/left alignment.
- System Back moves up one screen level before leaving the app.
- Light and Cool Dark themes are available in System settings.
- Secure mode never silently falls back to ordinary SMS or MMS.
- There are no accounts, analytics, ads, telemetry, or EutherPing relay.

Secure text uses Tink HPKE (X25519, HKDF-SHA-256, AES-256-GCM) plus Ed25519
signatures. Secure attachments use a fresh AES-256-GCM content key; the signed
manifest and key are HPKE-encrypted for the verified Vessel. The encrypted file
travels directly over local Wi-Fi, while its encrypted offer travels in Secure
Ping SMS capsules.

This remains **Secure Beta**. It does not have a Double Ratchet, forward
secrecy, post-compromise security, replay tracking, groups, or secure backup.
Do not strengthen the marketing claim until those properties and an external
security review exist.

## What changed in 0.6.4

### Fast conversation startup

Previously both Samsung and GrapheneOS could spend a long time reading Android's
Telephony provider before showing any active conversations. Version 0.6.4 now
uses a private, atomic conversation index at
`files/conversation-index-v1.json`:

1. The cached Signals and Vessels rows are rendered during the first Compose
   frame.
2. The full Telephony provider refresh runs on an IO dispatcher.
3. Provider notifications are debounced by 450 ms.
4. MMS parts remain lazy and contact-name completion does not cause another
   provider pass.
5. A null provider cursor is treated as an error and cannot wipe a good cache.

Ordinary SMS previews may be cached. Decrypted Secure Ping text is deliberately
replaced by `Encrypted Secure Ping // syncing…`; secure plaintext is not written
to the conversation index.

The first launch of 0.6.4 has no index and must build it once. The important
physical-device acceptance test is the second launch after a completed sync.

### Secure Echo `Operation not permitted`

The observed image-send failure is consistent with GrapheneOS denying the
app-specific Network permission. Secure attachment hosting opens a local
`ServerSocket`, so both phones need EutherPing's Network toggle enabled and must
be reachable on the same Wi-Fi.

`SecureAttachmentRepository` now preflights the permission and translates
`SocketException`, `ErrnoException`, `EPERM`, and `Operation not permitted` into
an actionable GrapheneOS settings message instead of showing the raw exception.

## Known unfinished work

- Physical carrier-MMS testing is still required across Samsung/GrapheneOS,
  SIMs, APNs, mobile-data-off, roaming, Wi-Fi calling, retry, and receive paths.
- The direct attachment sender must remain available, offers expire after 24
  hours, and files are limited to 256 MB.
- There is no relay, Bluetooth transport, resumable chunking, or background
  foreground-service hosting yet.
- Multi-SIM selection, group MMS, video/audio MMS, blocking, and backup are not
  implemented.
- The next security milestone should be a reviewed ratcheting session protocol
  with replay protection, not a home-grown cryptographic primitive.

The detailed current behavior is also documented in `README.md`,
`docs/SECURE_ATTACHMENTS_AND_MMS.md`, `docs/PRIVACY.md`, and
`docs/GOOGLE_PLAY_RELEASE.md`.
